PITCHLAB R23
YIN PITCH TRACKING RESEARCH, VALIDATION AND ARTIFACT-FREE DSP INTEGRATION
1. Mission
The objective of R23 is to establish a reliable, accurate, low-latency and artifact-free YIN-based pitch tracking subsystem for PitchLab Harmonizer.

This is not simply an algorithm implementation task.

We need to understand the mathematical foundations of YIN, evaluate available implementations, establish a robust real-time processing architecture, and integrate the resulting pitch estimates into the existing pitch-shifting engine without introducing audible artifacts.

The priority is audio integrity and stable tracking, not minimum CPU consumption at any cost.

The investigation must also address the previously reported PitchLab problems:
1. High-frequency crackling during negative pitch movement.
2. Unexpected stereo offset with a single voice and dual-mono input.
3. Plugin processing becoming silent or stuck while the DAW remains responsive.
4. No obvious audible or CPU differences between the R21 detector/interpolation builds.
Do not assume these symptoms originate in YIN. Investigate the detector, control layer, pitch shifter, stereo path and VST3 integration independently.

16.1 Existing detector behavior to verify against source
The R22 native source currently appears to contain three detector modes: FullRate, Decimated and Hybrid. Verify every item below against the exact R22 source and record the exact file/function/line evidence. Do not accept this list as a substitute for source review.

The current implementation appears to use:
- Default detector lower validity floor f0_min = 60 Hz, configurable in [20, 200] Hz.
- Upper detector validity limit 1200 Hz.
- A threshold value of 0.20 in the FullRate, Decimated and Hybrid candidate-selection paths.
- A first-local-minimum-below-threshold search, followed by a global minimum fallback if no acceptable local minimum is found.
- A FullRate window law max(2048, ceil(2.5 * tau_max)).
- A Decimated window law max(1024, ceil(2.5 * tau_max_dec)).
- A fixed comparison segment length derived as m = window_size / 2 - tau_max.
- Comparison samples taken from the second half of the rolling window, with the shifted segment at tau samples offset.
- FullRate cumulative normalization beginning at tau_min, not at lag 1.
- Decimated/Hybrid cumulative normalization warmed from max(2, tau_min - 18), also not necessarily from lag 1.
- FullRate parabolic refinement on the CMNDF array.
- Decimated coarse refinement on the raw difference function.
- Hybrid coarse search on the decimated signal followed by a narrow full-rate raw-difference refinement.
- A causal sixth-order Butterworth anti-alias filter in the decimated modes, with the existing cutoff law to be measured rather than assumed adequate.
- A decimation factor intended to keep detector rate near 24 kHz.
- A detector update cadence of detection_interval stream samples, with R22 default 64.
- A rolling period history, with default f0_history = 8, followed by a median before spacing-target calculation.
Important: the current FullRate implementation is the historical project reference, not automatically a mathematically canonical implementation of every step of the 2002 YIN paper. Use the label legacy FullRate reference where appropriate. Do not use “FullRate equals canonical YIN” unless the source comparison proves it.
16.2 Critical distinction: YIN output does not directly drive the voice pitch ratio
The existing engine does not use the detector's estimated f0 as the per-voice transposition ratio.

The current path appears to be:

input samples -> YIN detector -> f0 estimate -> period (sample_rate / f0) -> period history/median -> S_target -> grain-wrap spacing commit -> delay/grain rendering

The voice's actual transposition ratio is a separate per-voice control (ratio / ratio_t) derived from the voice interval or ratio parameter. The grain phase update uses the ratio together with the spacing state.

Therefore, the earlier generic requirement that the new Pitch Control Layer should output a “continuous pitch-ratio trajectory” is not an accurate description of the current architecture and must be corrected.

The R23 design must explicitly distinguish:
1. Input F0 estimate: what pitch/period the detector believes is present in the input.
2. Tracking decision: whether the estimate is trustworthy and should update the engine's input-period/spacing history.
3. Engine spacing target: the existing grain-spacing target calculated from the accepted input period.
4. Per-voice transposition ratio: the musical interval applied by each voice; this is not the detector F0 and must not be overwritten by the new tracker.
5. Audio read/grain state: the pitch shifter's own per-sample phase, delay and interpolation machinery.
The new Pitch Control Layer should initially be specified as an Input Pitch/Period Tracking and Spacing-Control Gate. Its output contract should carry a validated F0 or period estimate plus tracking state. It should feed the existing spacing-target/history pathway through an explicitly documented interface. It must not silently replace the per-voice ratio_t control.

The agent must compare at least three integration strategies:
- Keep the existing 8-entry period median and add only detector confidence/outlier gating before it.
- Replace the existing median with a more explicit stateful tracker.
- Combine a confidence/lock state machine with the existing median, while proving that latency is not doubled unnecessarily.
Measure the behavior and total latency of each strategy. Do not stack multiple smoothing filters by default.
16.3 Existing grain and crossfade path must be audited accurately
Inspect the actual current readVoiceAt weighting function and grain phase law. The R22 source appears to contain a raised-cosine/half-cosine weighting law of the form:

w = 0.5 - 0.5 * cos(pi * frac)

and the grain phase increment appears to use:

frac_next = frac + (1 - ratio) / S

Verify these expressions in source.

Earlier artifact notes refer to a triangular window. Do not repeat that claim unless the exact active R22 code path actually uses a triangle. If the implementation is already a half-cosine, identify which other mechanism could create the observed high-frequency crackle.

Under ordinary resampling, the aliasing risk depends on the read-rate direction; the granular implementation may introduce additional modulation sidebands, so analyze its actual transfer behavior rather than importing a generic rule.

17.1 Signal model and what YIN estimates

- perceived pitch;
- a dominant spectral component;
- the pitch of a polyphonic mixture;

17.2 The autocorrelation starting point and why YIN changes it
Explain the conventional autocorrelation function and its failure modes:
- amplitude variation across the frame;
- selection of a higher-order period peak;
- the difference between fixed-window and shifted-window/biased definitions;
- why the energy of the shifted window cannot always be treated as constant.
Derive the relation between the difference function and autocorrelation:

d_t(tau) = r_t(0) + r_(t+tau)(0) - 2*r_t(tau)

Use the exact index conventions from the original paper and define them clearly. Explain why dropping the shifted-energy term is not generally valid.
17.3 Difference-function support: mandatory distinction
This is one of the most important research topics and must not be compressed into a single formula.

Define separately:
- W: number of difference terms integrated at each lag;
- tau: candidate period/lag;
- N: finite input frame or buffer length;
- N_required: total input support needed to evaluate a fixed-W difference function up to tau_max.
For a fixed integration length W using a one-sided frame definition, the input support must include both the W-sample reference segment and its shifted copy. In other words, the required input support grows with the maximum lag (approximately W + tau_max, subject to the exact indexing convention).

A different common implementation uses a fixed N-sample frame and sums only N - tau terms at each lag. This changes the integration length as a function of tau. It is a valid implementation convention used by established libraries, but it is not identical to the fixed-W formulation. The agent must derive and compare both forms, not mix their indexing rules.

Also inspect symmetric window alignment, where the reference and shifted windows move symmetrically around the analysis timestamp. This changes timestamp alignment and latency behavior.

For every variant document:
- exact summation limits;
- number of terms per lag;
- required buffer support;
- timestamp represented by the estimate;
- edge padding/startup behavior;
- whether integration duration changes with tau;
- numerical equivalence or non-equivalence.
17.4 CMNDF derivation and interpretation
Derive the cumulative mean normalized difference function:

d'(0) = 1

d'(tau) = d(tau) / ((1/tau) * sum(d(j), j=1..tau))

Explain:
- why the zero-lag value must be handled specially;
- why normalization is cumulative from lag 1 in the canonical definition;
- how truncating the cumulative sum below tau_lo changes the result;
- how CMNDF responds to amplitude scaling;
- how numerical guards should behave for silence, DC and near-zero cumulative energy.
The R22 detector appears to begin its running normalization at tau_lo, with FullRate using tau_min and Decimated/Hybrid warming only a bounded number of lags below the search floor. Quantify the difference between this truncated normalization and canonical CMNDF for actual PitchLab parameter ranges. Do not automatically change it: preserve the legacy path as a baseline and measure alternatives.

The original paper interprets the normalized difference at the period as approximately related to the aperiodic-to-total power ratio. This is not a calibrated probability. In particular, do not define confidence = 1 - CMNDF_min and then report it as a probability without calibration. Use names such as clarity, periodicity_score or aperiodicity_measure until a calibrated probability model is demonstrated.
17.5 Absolute threshold and candidate-selection semantics
Document the exact canonical rule:
- find local minima of CMNDF;
- choose the smallest lag whose minimum is below the threshold;
- if no such minimum exists, the original method falls back to the global minimum in the allowed search interval.
Do not simplify this into “reject frame if no trough is below threshold” unless that is deliberately tested as a different detector mode.

Compare at minimum thresholds 0.05, 0.10, 0.15, 0.20 and 0.40, but also report distributions of minimum values on voiced and unvoiced audio. Do not infer that 0.15 is best from a single synthetic corpus.

Separate these decisions:
- selecting a period candidate;
- deciding whether a frame is voiced/periodic enough to use;
- deciding whether the estimate should update the existing engine's spacing history.
They are three related but distinct gates.
17.6 Parabolic interpolation: canonical nuance and implementation alternatives
The original paper's Step 5 has a specific nuance:
- fit a parabola around each local CMNDF dip;
- use the interpolated dip ordinate in the candidate-selection process;
- the paper notes a bias in the interpolated CMNDF abscissa and uses the abscissa of the corresponding raw difference-function minimum for the period estimate.
Many practical implementations instead directly parabolically refine the selected CMNDF minimum. Others refine the raw difference function. These are not automatically identical.

Implement or script a reference comparison for:
1. integer-lag estimate;
2. parabolic interpolation on CMNDF;
3. parabolic interpolation on raw difference function;
4. original-paper selection/refinement behavior;
5. a more accurate local interpolation alternative if useful.
For every approach test boundary minima, flat valleys, non-convex neighborhoods, near-zero curvature and strong high-frequency content. The original paper specifically discusses reduced parabolic accuracy when strong components exist above roughly one-quarter of the sampling rate. Test this behavior instead of assuming three-point interpolation is universally accurate.

Use a scale-aware numerical guard for interpolation on raw d(tau) values. A single fixed absolute epsilon can behave differently when input level changes because the raw difference values scale approximately with signal amplitude squared.
17.7 Original YIN Step 6: Best Local Estimate
This must be researched and documented separately from Pitch Control Layer smoothing.

The original paper's Step 6:
- examines estimates in a temporal neighborhood around each analysis time;
- searches approximately [t - T_max/2, t + T_max/2] for a better-quality estimate using d'_theta(T_theta);
- re-runs the estimator using a restricted lag range around the chosen candidate (the paper's example uses approximately ±20%);
- selects based on estimate quality, not merely smoothness or continuity.
The original evaluation reports a gross-error reduction from approximately 0.77% after Step 5 to 0.50% after Step 6 in its specific speech evaluation setup. Do not assume this gain transfers to PitchLab.

Exact Step 6 requires future context around the target time and therefore introduces look-ahead/latency in a real-time implementation. Evaluate:
- exact non-causal/original Step 6 as an offline reference;
- buffered real-time Step 6 with explicit look-ahead;
- causal approximation using only past/current frames;
- omission of Step 6 with a separate Pitch Control Layer.
Quantify the extra latency and quality difference. Do not rename a median filter or a hysteresis state machine as original YIN Step 6.
