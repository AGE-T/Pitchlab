# 11. P0 — AUDIO CALLBACK MUST NOT SLEEP

Known source finding:

`pitch-lab/src/vst/realtime_adapter.cpp`

contains a path equivalent to:

```cpp
std::this_thread::sleep_for(std::chrono::microseconds(250));
```

inside realtime processing startup assistance.

The loop can wait approximately 25 ms.

This violates the project's own realtime requirement.

### Required

Find a design where the audio callback never:

* sleeps,
* waits,
* busy-waits,
* blocks,
* joins.

The initial chain must be prepared before the audio callback requires it, or the callback must take a genuinely non-blocking fallback path.

No mutex replacement.

No hidden wait.

Add regression / structural protection where practical.
