   124→## 2. Execution topology (OBS)
   125→
   126→The graph is compiled **twice** (two parallel call trees):
   127→
   128→| role | worker A | worker B |
   129→|---|---|---|
   130→| audio/voice worker (calls prepare `0x1800e2030` and voice filter `0x1800e8b50`) | `FUN_180103a10` | `FUN_18011d5f0` |
   131→| control/tracker worker (calls pitch worker `0x1800e5160`, rdm slew, c_multiply, c_adder8) | `FUN_1801061a0` | `FUN_18011fd60` |
   132→| owner that instantiates the module (`FUN_180137e20`) | `FUN_1800f00a0`, `FUN_180109d40` | `FUN_180122e00` |
   133→
   134→**OBS** — `procedure_callers` gives exactly these on both sides; the deltas between A and B are not a
   135→constant byte shift, so this is **not** a duplicated function body but two instantiations of the same
   136→module class in two graph positions.
   137→
   138→**DER (RESOLVED in round 2)** — the function pairs are **per-IO-profile clones of the same graph
   139→executor**: `FUN_180103a10` / `FUN_18011d5f0` are 475 / 474 lines, `FUN_1801061a0` / `FUN_18011fd60`
   140→are 307 / 306 lines, and a diff shows only operand-order swaps in a few multiplies plus different
   141→module **base offsets**. One of them references `param_1 + 0x1E990`, which is `monoSumWetChans` — a
   142→module that exists **only in the `mimo` profile** (D1 §6.0) — so the trees correspond to the shipped
   143→kernel profiles (`mimo`, `miso`, `siso`, …), not to left/right channels and not to a monitor branch.
   144→See D7 Q-1.
   145→
   146→### 2.1 Per-block entry sequence (engine prepare, `FUN_1800e2030`)
   147→
   148→1. **Input capture** — `p = **(engine+0x60)`; push `p[0..3]` into the input history ring at
   149→   `(write & mask), (write-1 & mask), (write-2 & mask), (write-3 & mask)`; i.e. the newest sample
   150→   sits at index `write`, and reading `ring[(write + d) & mask]` yields the sample `d` samples ago.
   151→   Afterwards `engine+0x41b8 = write - 4` (L49-59, L304-308).
   152→2. **Tracker call** — `FUN_18013bbc0(engine+0x4518, p+1, 1)`. Tracker input is therefore
   153→   `p[1]` and (inside) `p[3]` — **2 of every 4 input samples** (L60).
   154→3. **Per-voice loop**, `v = 0 .. nvoices-1` (L63-302):
   155→   a. gain ramp: `g = clamp(target[v] - current[v], -1, 0)`, `current[v] = g` (L72-82);
   156→   b. windowed delay: for `k=0..3` write `work[v][(wp-k)&mask] = -(g * ring[(D_v + k') & irmask])`,
   157→      update the per-voice write pointer (L83-113);
   158→   c. rate pipeline: quartic `q(x)` from `+0x40d8..+0x40e8` applied to `x = control_in[v] * page[10]`,
   159→      multiplied by `page`-derived factor and `64`, giving the read-rate increment `dVar33` (L114-125);
   160→   d. page select: page A unless `selector[v] == 1` → page B (L126-128);
   161→   e. **read** at fractional position `pos_v` (double, `+0x4188[v]`) from the per-voice work ring,
   162→      with 6-tap Lagrange interpolation selected by `((int)(pos*2048) & 0x7F8) >> 3` (L132-278);
   163→   f. two sub-paths selected by `(int)crossfade_state[v] == -1`:
   164→      * `!= -1` (L231-278): **crossfade mix** of two taps `D_v` apart, ramp state decremented by the
   165→        period-correction value, clamped at −1;
   166→      * `== -1` (L133-229): direct interpolated read, then the **record/period** update:
   167→        read the 4-float tracker record from ring `+0x98`, map period → page column, apply
   168→        power-of-two period scaling, update the integer delay `+0x4140[v]` and re-arm the crossfade
   169→        `+0x4158[v] = 0` (L163-228);
   170→   g. **ratio glide**: slew `page[0]` toward `page[1]` using `+0x44e0` (up) / `+0x44f8` (down);
   171→      `page[1] = page[next_index + 2]` (L280-299);
   172→   h. store `pos_v` as a double (L300).
   173→4. `engine+0x41b8 -= 4` (ring bookkeeping, L304-308).

   177→## 3. Stage-by-stage specification
   178→
   179→### S1 — Input bus / block framing
   180→* **Function/IO**: `FUN_1800e2030` L48-59. In: host audio block (bus `engine+0x60`); out: 4 samples
   181→  appended to the input history ring.
   182→* **State**: `engine+0x41a0` ring, `+0x41b8` write index, `+0x41c0` mask.
   183→* **Conditions**: unconditionally, once per 4-sample sub-block.
   184→* **Param deps**: none.
   185→* **Downstream**: S2 (tracker), S4 (voice windowing).
   186→
   187→### S2 — Pitch analysis / tracker
   188→* **Function/IO**: `FUN_18013bbc0(engine+0x4518, p+1, 1)`. In: 4 raw input samples, of which
   189→  `p[1]` and `p[3]` are used. Out: 4-float records pushed into `engine+0x98` (mask 0xFFF).
   190→* **State / execution conditions / params**: see D2 in full.
   191→* **Downstream**: S3 (record read), and `m02` read-out ids 7..0xd.
   192→
   193→### S3 — Record read and period/interval mapping
   194→* **Function/IO**: `FUN_1800e2030` L163-228. In: record ring `+0x98`, per-voice read index
   195→  `+0x42f8[v]` plus `+0xa4fc`; out: updated per-voice integer delay, crossfade arming, page column
   196→  selection.
   197→* **Key arithmetic (OBS)**:
   198→  * `idx = (record_index[v] + engine[0xa4fc]) & 0xFFF`;
   199→  * `period = ring[idx] * 2^-11` (× 0.00048828125), then clamped: `period ≥ 48`, or `= 480` if
   200→    `period < 7.1054e-15`;
   201→  * `next = ring[(idx+1) & 0xFFF]` (an **integer-valued float** = interval/candidate index);
   202→    if `engine+0x4510 == 0` (pitch tracking off) `next = 1.0` and `idx2 = 0`;
   203→  * `rate = page[0] * ring[(idx+3) & 0xFFF]` → written to `float[nv] @ +0x4128` (round 9/12; **round 15 Q-A proved the idx+2 read never exists** — see `evidence/analysis_round15/NOTES.md`);
   204→  * `col = clamp((period-48)*0.0625, 0, 31)`; `c = page[col + 12]`;
   205→    `float[nv] @ +0x4110 = c * 2^-23`; `period = 2^(c & 0xF) * period + 0.5`, rounded to int
   206→    with a floor correction (L199-206);
   207→  * crossfade/limit test against `page[0xb]` and the work-ring mask (L207-228).
   208→* **Param deps**: `page` contents (port 21/22), `+0xa4fc`, `+0x4098`.
   209→
   210→### S4 — Per-voice gating window
   211→* **Function/IO**: `FUN_1800e2030` L72-113. In: current & target voice gain arrays, input ring.
   212→  Out: 4 gated, delayed samples per voice written into the per-voice work ring.
   213→* **State**: `engine+0x4208[nv]`, `engine+0x40a0`, `engine+0x40c0[nv]`.
   214→* **Conditions**: always; `g ≤ 0`, `|g| ∈ [0,1]` is the voice gain.
   215→* **Downstream**: S5.
   216→
   217→### S5 — Variable-rate delay read (pitch shifter core)
   218→* **Function/IO**: `FUN_1800e2030` L114-278. In: per-voice work ring, read position `pos_v`,
   219→  increment `rate_v`. Out: 4 output samples per voice into the per-voice output port.
   220→* **Arithmetic (OBS)**:
   221→  * control input `f = F * slot_40F8[v]` where **F = the mod-port data element [0]** (the port
   222→    table at `engine+0x68`, 0x10-stride, bound to the record's `mod<N>` entries = the `rdm slew N`
   223→    walk values ∈ [0,1] with `1.0` attainable (round-10 orbit proof); round 9 corrects the
   224→    earlier "input_port[v][1]" rendering — the `[1]`-like
   225→    offset is inside the port *table*, not the data);
   226→  * literal quartic (prepare L121-125, `fVar1 = x²`):
   227→    `q = (+0x40e8)·x⁴ + (+0x40e4)·x³ + (+0x40e0)·x² + (+0x40dc)·x + (+0x40d8)`,
   228→    then `rate_v = (float32)q * rate_slot[v] * 64.0` where `rate_slot = float[nv] @ +0x4128`
   229→    = `(ratio/16)·correction` — so **`rate_v = 4·q(f)·ratio·correction`** with unity at `f = 0`
   230→    (round 9; see §8);
   231→  * read index phase = `((int)(pos_v * 2048.0) & 0x7F8) >> 3` → 0..255 — i.e.
   232→    **`floor(frac(pos_v)·256)`** (round 12, instruction level at `0x1800E2490–0x1800E24AD`);
   233→  * interpolator = 6 taps read from `+0x40f0 + 0x18*phase`, applied to 6 consecutive work-ring
   234→    samples starting at `(wp + (int)pos_v) & mask`.
   235→    **Round 12 (OBS): `+0x40f0` points to a STATIC 256×6-float table in `.rdata` at VA
   236→    `0x1803B6170`** (installed by `FUN_1800E18B0` at `0x1800E1FB4/0x1800E1FBB`, together with
   237→    the five quartic immediates at `0x1800E1F82–0x1800E1FAA`). The kernel is **not 6-point
   238→    Lagrange** (the old member-map label is corrected): row sums 1.000000–1.000122 (unity DC),
   239→    effective fractional delay sweeps 0.0020→0.9980 (bin-centre phases `(r+0.5)/256`, DER),
   240→    mirror-symmetric rows, best-aligned Lagrange L2 mismatch 0.11–0.19 rms — a designed
   241→    symmetric lowpass kernel (windowed-sinc-like, DER). Bit-exact extraction:
   242→    `evidence/analysis_round12/r12_obs_kernel_table.h`; analysis: `r12_interp_table.txt`.
   243→    The settle/crossfade paths both read through this one table.
   244→  * `pos_v` advances by `rate_v` per output sample, clamped `≥ 0` (`dVar11 = pos - rate; if (<0)
   245→    dVar11 = pos`), and by **`+4.0` per 4-sample block** (const `4.0` @ `0x1804123E8`, added at
   246→    `0x1800E224D`) — net block motion `4·(1−rate)`, i.e. **zero at rate exactly 1.0** (round 12).
   247→* **Conditions**: per voice, always.
   248→* **Param deps**: `page[10]`, quartic coefficients, `page`-rate slot, `+0x4098`.
   249→* **Downstream**: S6.
   250→
   251→### S6 — Crossfade / delay jump
   252→* **Function/IO**: `FUN_1800e2030` L231-278 (active) and L207-228 (re-arm). In/out: the same output
   253→  bus; internal state `+0x4158[v]`, `+0x4140[v]`.
   254→* **Arithmetic (OBS)**: `mix = (tapA - tapB) * state + tapA`, with `state` decremented each
   255→  output sample by `slot_4110[v] = page[12+idx]·2^-23` and clamped at −1. `tapA`/`tapB` differ
   256→  by the record **interval** (tapA at `ringbase − interval`, tapB at `ringbase`, round 12
   257→  instruction level).
   258→* **Conditions**: `(int)state == -1` → settled path with record update; otherwise crossfade path.
   259→  **Round 12 (OBS, instruction level): the settled path computes exactly ONE 6-tap interpolated
   260→  read per output sample** (loop `0x1800E2490–0x1800E25D5` — one phase row, six consecutive
   261→  work-ring samples, no second tap, no blend). The crossfade is a one-shot linear fade that
   262→  SETTLES back to single-tap; the engine's rest state is a single interpolated tap.
   263→* **Re-arm**: trigger `pos − delay[v] < 8.000000000000007` (double @ `0x180412428`);
   264→  jump `floor(2^((int)page[12+idx] & 0xF)·v + 0.5)` where
   265→  `v = clamp(ring[recidx]·2^-11, ≥ 48.0; 480.0 if ≈0)` and
   266→  `idx = clamp(int((v−48)/16), 0, 31)`; the jump is halved when it would reach
   267→  `≥ mask − page[11]`; on re-arm `+0x4140[v] = pos ∓ jump`, `+0x4158[v] = 0`
   268→  (`0x1800E275E–0x1800E2809`). The record read index is
   269→  `(recidx[v] (+0x42f8) + wdelta (+0xa4fc)) & 0xFFF`; `ring[recidx+3]` is the correction
   270→  (confirms round 9); `ring[recidx+1]` as int is the interval. **Unity consequence (DER)**:
   271→  at rate exactly 1.0 `pos` is frozen, the re-arm never fires, and the engine rests in the
   272→  settled single-tap path — a fixed fractional delay with **no two-tap comb** (see

   275→### S7 — Per-voice modulation filter (`FUN_1800e8b50`)
   276→* **Function/IO**: In: per-voice ports `+0x58`/`+0x68`/`+0x78` (control sources) and constants;
   277→  out: four 4-sample control vectors at `**(engine+0xa8/0x90/0xc0/0xd8)`.
   278→* **Arithmetic (OBS/DER)**: a **Chamberlin-style 2nd-order state-variable filter** with
   279→  `f = clamp(src1*k + b)`, `q = clamp(src2*k2 + b2)`, states `a` (band) and `b` (low):
   280→  `low = f*a + b; high = (x - low) - q*a; f1 = high; a' = f*a + high;`
   281→  outputs `high`, `low`, `notch = high+low`, `band = a'`, each scaled by the voice-level ramp
   282→  `fVar7 = clamp01(+0x188 + +0x190)` (ramp accumulator written back to `+0x190`).
   283→* **State**: `+0x194` (b), `+0x198` (a) per voice instance.
   284→* **Conditions**: called once per 4-sample block per voice by `FUN_180103a10`/`FUN_18011d5f0`.
   285→* **DER**: acts as the per-voice **glide/smoothing generator** producing the modulation control
   286→  vectors consumed by S5.
   287→* **Downstream**: control ports consumed by S5 (and `rdm`/`c_multiply` graph).

   578→### 6.2 Random-modulation subsystem (8 parallel chains, OBS)
   579→
   580→Structure of chain N (N = 1…8); the dump's names are **rotated**, see the note below:
   581→
   582→```
   583→rdm abs  = |rdm noise|                       (one shared noise source [213])
   584→rdm sh N = sample&hold(rdm abs) triggered by rdm comp N
   585→rdm slew N : in = rdm sh N, pslew = nslew = rdm mult ?  → slew-limited random walk
   586→rdm comp N : in1 = rdm slew N, in2 = rdm sh N            → re-arm comparator for the S&H
   587→rdm a-c N  : in = rdm slew N                             → the chain's output
   588→rdm mult ? : 2000 · ( rdm a-c ? / 1.5 + 0.5 )            → slew amount (0…2000 units)
   589→dtonicii9.mod1…mod8 ← rdm slew 1…8                       (engine input, full record)
   590→dtonicii9.modamt1…mod8 ← rdep                            (engine input: the *depth*)
   591→multiply12 [244] = c_fltr_a36 · rdm slew 1               (c_fltr_a36 = smoothed(rdep/2400), tc 20)
   592→```
   593→
   594→* `rdep` [10] = "rnd dpth" `0…200`, default 50; `c_divide26` [11] = `rdep/2400` → `c_fltr_a36` [12]
   595→  (tc 20).
   596→* **Name rotation (OBS):** the module names are not aligned with the chains. `rdm mult 2` … `rdm mult 8`
   597→  take their input from `rdm add 1` … `rdm add 8` respectively, and `rdm mult 1` takes `rdm add 8` —
   598→  i.e. the amplitude multipliers carry a name one *higher* than the chain they serve, wrapping around.
   599→  The same rotation appears in the voice chains (§6.1: voice 1 is served by `modfilter8`, `moddelay7`,
   600→  `multiply4`). The chains themselves are unambiguous when followed by reference; the numbers in the
   601→  names are not.
   602→* **`rdep` delivery (round-4 correction, OBS):** `rdep` [10] has two live readers — `c_divide26` (the
   603→  dead `c_fltr_a36 → multiply12 → add8` normaliser) **and `dtonicii9.modamt1..8`** (record entries
   604→  44–52). So `rdep` is delivered to the engine as the per-voice **random-modulation depth**, exactly
   605→  as the record states (`modamt1..8 = rdep-out`); the `c_fltr_a36`/`multiply12` path is the dead
   606→  artifact. The engine's `modN` inputs are the slew-limited walk itself.
   607→* The modulation is therefore a slew-limited random walk: the walk value (`rdm slew N`) is the
   608→  engine's `modN`, and its **depth is `rdep`** (`modamtN`). The old "`mod1…mod7` only / `mod8`
   609→  truncated" note is retracted — `mod1..mod8` are all present (§6.1).

   627→## 8. Round-9 addendum — the rate map resolved (2025-10-23)
   628→
   629→The two rate-map fields are private zero-filled `std::vector<float>` members of the dsp_t
   630→(which lives at **wrapper+0x430**), constructed in `FUN_1800E0360` and destroyed in
   631→`FUN_1800E7DF0` (the round-8 "in-place-constructed objects at 0x1800E7EF6/0x1800E7F0E" reading is
   632→retracted — `FUN_180010E30` is the `vector<float>` **destructor**). Their element values are
   633→written and read **only** by the prepare, per voice per block:
   634→
   635→```
   636→slot_40F8[v] = page[10] = clamp(modamt_v, lo, hi)·(1/2400)         ; modamt = rdep ("rnd dpth", 0…200)
   637→slot_4128[v] = page[0] · ring[(idx+3) & 0xFFF]                     ; fallback page[0] when ~0
   638→               page[0] = ratio·0.0625 = ratio/16                    ; exp(cents·ln2/1200)·0.0625
   639→               ring[(idx+3)] = the tracker's running correction gain
   640→
   641→f    = F · slot_40F8[v]            ; F = the rdm slew N walk value ∈ [0,1] (1.0 attainable;
   642→                                   ;  arithmetic bound [0,1+2^-23], absorbed by the P rounding
   643→                                   ;  at the tested depths, ≤ one P-ulp elsewhere — rounds 10–11)
   644→step = (float32)P(f) · slot_4128[v] · 64.0 = 4·P(f)·ratio·correction
   645→pitch = |step| · f_in              ; backward read; a step > 1 is upward
   646→```
   647→
   648→* **Unity is exactly `f = 0`** (no random modulation): `4·P(0) = 1`. The round-8 `R = ratio/64`
   649→  hypothesis and its unity locus are **retracted** (the page scale is `0.0625 = 1/16`, a factor-4
   650→  error; the `64.0` multiplier and the `1/16` scale cancel to 4, which cancels `P(0) = 1/4`).
   651→  **The total output ratio is `ratio · correction · 4·P(f)` — three distinct factors** (the
   652→  configured ratio from the temperament tables, the tracker's running correction `T+0x6070`,
   653→  and the random modulation); it equals the configured ratio **only when `correction = 1`**
   654→  (in particular with pitch tracking off, where the correction is hard-set to `1.0`).
   655→* **`4·P(f) ≈ 2^(2f) = 2^(cents/1200)`**: the quartic is the engine's polynomial cents→ratio
   656→  curve, with `f = deviation/2400` (units of ±2 octaves). The random modulation therefore
   657→  applies **`walk·depth` cents** to the voice ratio — to within the quartic's fit error
   658→  **`|cents − walk·depth| ≤ 0.101 ¢`** over the shipped range (round 11: interior maximum at
   659→  `f ≈ 0.0561` → `F ≈ 0.673` at depth 200, achieved cents slightly **below** nominal in the
   660→  bulk — the "upward" character is the modulation *direction* `4·P ≥ 1`, not the error sign);
   661→  at the maxima **49.939 ¢** (depth 50) / **199.923 ¢** (depth 200). *(Round 10 corrected the
   662→  earlier example values 50.13/201.68 ¢, which were calculation errors; round 11 corrected the
   663→  max-error location and the residual-direction wording.)*
   664→* The graph binding is fully identified: `rdep` → `modamt` entry (wrapper+0x2B0, name "modamt"
   665→  at `0x180408420`) → page[10]; `rdm slew 1..8`-out → `mod1..8` → the `+0x68` port table (bound
   666→  in `FUN_1800E18B0`) → F. The noise generator is module **[212] `rdm noise`** (add_fn
   667→  `0x180139C50`, process `FUN_180139B40`, missing from the round-4 dump): a lagged-Fibonacci
   668→  additive generator with scale `0x34000001 = 2^-23·(1+2^-23)` — arithmetic output range
   669→  `[−(1+2^-23), +1.0]`, and over its actual orbit (default config, full period `2^22`) exactly
   670→  `[−1.0, +1.0]` (round 10).
   671→* Full evidence: `OCTAVOX_ROUND9_FINDINGS.md` (numeric layer corrected by
   672→  `OCTAVOX_ROUND10_FINDINGS.md`, audited by `OCTAVOX_ROUND11_FINDINGS.md`); D6 §13 rows R-43–R-59.
   673→  Runtime behaviour (walk statistics, correction convergence, audible character of the
   674→  one-sided (upward-from-base) deviation) stays **UNK** — the target was never executed.
