    11→    11→### A very abridged physics of sound
    12→    12→When we listen to pitched sound, the 'pitch' of what we are hearing is often described in terms of frequency. This is because the way our ears perceive sound is through hearing the intensity (amplitude) and frequency at which the sound (a pressure wave) is hitting our eardrums. The simplest example is a pure sine wave, which we can easily manipulate the frequency of to produce different pitches.
    13→    13→
    14→    14→However, these pure waves often sound 'harsh' and obviously synthetic. And audio waves with no distinct noticable periodicity are often perceived not as pitched, but as 'noise'. This is again due to the lack of some distinct patterning frequency which our ears can attune to.
    15→    15→
    16→    16→### Pitch detection algorithms
    17→    17→The goal of pitch detection algorithms is to parse together the often complex frequency waveforms to find the repeating unit of pitch which corresponds to the 'pitch'. Since humans have an innate subjective sense of pitch and for parsing out these complex waves in our own ears, we want the algorithm to also determine the pitch and recreate the processes happening in our brains, computationally.

   146→   146→# Pitch Detection: Autocorrelation
   147→   147→
   148→   148→**Autocorrelation**-based methods represent one of the most popular categories of pitch detection algorithms, and is also the method which underlies the YIN algorithm. It tries to analyze the audio signal within the *time domain* by detecting how similar the signal is to a shifted version to itself.
   149→   149→
   150→   150→### Problem statement
   151→   151→We have some audio signal $x$, represented as a numpy array of samples, where each sample contains a quantized representation of the pressure of the physical audio wave at the given time of 'sampling'.
   152→   152→
   153→   153→**Basic idea:** We want to estimate the fundamental frequency $F_0$ for a given frame of audio data by comparing how different the original signal is to a signal shifted over by some lag. The specific lag which minimizes this difference, we call the fundamental period, which is equivalent to $1 / F_0$.
   154→   154→===== CELL 9 [markdown] 2364 chars =====
   155→   155→## Autocorrelation
   156→   156→We define the autocorrelation function $r_t(\tau)$ as a function of some $\tau$, which is a duration (in samples) of how much to x-shift each point in the curve by. 
   157→   157→
   158→   158→The goal of this function is to identify those periods under which the function most resembles itself. The function multiplies each new pair of x's together (where $x_j$ represents the audio signal value at the $j$ th sample), so higher values represent a value of $\tau$ under which the curve looks more like itself.
   159→   159→
   160→   160→$$r_t(\tau) = \sum^{t+W}_{j=t+1}x_j x_{j+\tau}$$
   161→   161→
   162→   162→Equation from the YIN paper [1]
   163→   163→
   164→   164→In the code, we use a slightly modified definition from the YIN paper [1] which defines a second slightly different definition which allows the integration window size to shrink with increasing values of $\tau$.
   165→   165→
   166→   166→$$r_t(\tau) = \sum^{t+W-\tau}_{j=t+1}x_j x_{j+\tau}$$
   167→   167→
   168→   168→This makes it so that larger $\tau$ values are weighted slightly less, under the assumption that the true fundamental frequency is closer to the origin point.
   169→   169→
   170→   170→### FFT-enabled autocorrelation with Wiener-Khinchin
   171→   171→The **Wiener-Khinchin theorem** enables us to compute the autocorrelation much faster. We can rewrite the audio signal 'array' $x$ as a function $x(t)$ where $t$ is the index of the sample in the array. Then we can rewrite the autocorrelation function as an integral on this function $x(t)$ as such:
   172→   172→
   173→   173→$$r_t(\tau) = \int^{\infty}_{\infty} \bar{x}(\tau)x(t+\tau) d\tau$$
   174→   174→
   175→   175→where $\bar{x}(\tau)$ is the complex conjugate of $x$. A short proof of the theorem can be found at [[2](https://mathworld.wolfram.com/Wiener-KhinchinTheorem.html)], but the result that we are using for this autocorrelation implementation is the ability to compute the autocorrelation not by iterating through all possible samples for all possible frames and multiplying each sample pointwise, but rather it allows us to use the fast fourier transform which runs in $O(N \log n)$ time per frame, whereas the other method would be $O(N^2)$ per frame.
   176→   176→
   177→   177→It suffices to compute:
   178→   178→
   179→   179→$$r_t(\tau) = \mathcal{F}^{-1}(x) \left ( \left | \mathcal{F}(x) \right |^2 \right )$$
   180→   180→
   181→   181→where $\mathcal{F}(x)$ is the fourier transform of the audio signal. Note $\left | \mathcal{F}(x) \right |^2$ is also how we define the power spectrum of the signal, which shows how much each individual frequency component is contributing to the audio waveform.
   182→   182→===== CELL 10 [code] 1660 chars =====
   183→   183→# define autocorrelation function
   184→   184→def autocorrelation_fft(audio_frame: np.ndarray, tau_max: int) -> tuple[np.ndarray, np.ndarray, np.ndarray]:
   185→   185→    """
   186→   186→    Fast autocorrelation function using Wiener-Khinchin theorem,
   187→   187→    which computes autocorrelation as the inverse FFT of the signal's power spectrum.
   188→   188→
   189→   189→    Args:
   190→   190→        audio_frame: The current frame of audio samples in Yin algorithm
   191→   191→        tau_max: Check for all time lags up to this value for in autocorrelatioin
   192→   192→
   193→   193→    Returns:
   194→   194→        autocorrelation: The similarity curve
   195→   195→        power_spec: The power spectrum of the frame
   196→   196→        amplitudes: Amplitudes of the frame
   197→   197→    """
   198→   198→    w = audio_frame.size
   199→   199→    tau_max = min(tau_max, w)  # ensure tau_max is within the window size
   200→   200→
   201→   201→    # Zero-pad the audio signal array by the minimum power of 2 which
   202→   202→    # is larger than the window size + tau_max.
   203→   203→    # (circular instead of linear convolution, avoids errors)
   204→   204→    min_fft_size = w + tau_max  # (pad by >tau_max for frame end)
   205→   205→
   206→   206→    p2 = (min_fft_size // 32).bit_length()
   207→   207→    fft_sizes = (16, 18, 20, 24, 25, 27, 30, 32)
   208→   208→    size_pad = min(size * (2 ** p2) for size in fft_sizes if size * 2 ** p2 >= min_fft_size)
   209→   209→
   210→   210→    # -- Wiener-Khinchin Autocorrelation --
   211→   211→    # take FFT to decompose signal into its frequency components
   212→   212→    fft_frame = np.fft.rfft(audio_frame, size_pad)
   213→   213→    power_spectrum = fft_frame * fft_frame.conjugate()
   214→   214→    autocorrelation = np.fft.irfft(power_spectrum)[:tau_max]
   215→   215→
   216→   216→    amplitudes = np.abs(fft_frame)
   217→   217→
   218→   218→    # only return valid overlapping values up to window_size-tau_max
   219→   219→    # (type II autocorrelation from jasa 2002)
   220→   220→    return autocorrelation[:w-tau_max], power_spectrum, amplitudes

   268→   268→## YIN's CMNDF
   269→   269→YIN's unique contribution to autocorrelation-based pitch detection methods is its **cumulative mean-normalized difference function** (CMNDF). We will first define the raw difference function, then see how YIN modifies it, then see how we use the curve to detect periodicity in the audio signal.
   270→   270→
   271→   271→### Background: The difference function
   272→   272→If we assume that the signal is periodic with some period $T$, we can construct an equality which we can solve to form a 'difference function' which is able to be minimized to find the period (or 'lag' in autocorrelation terms) under which the signal most closely resembles itself.
   273→   273→
   274→   274→We can model a periodic signal $x$ with period $T$ to be by definition invariant when we shift it by that period:
   275→   275→
   276→   276→$$x_t - x_{t+T} = 0 \quad \forall t$$
   277→   277→
   278→   278→Which can be rewritten to still equal $0$ after squaring the result and summing the result over a window of different $t$ values. We use this fact to construct the following definition of the difference function $d_t(\tau)$, and search for values of $\tau$ which minimize this difference.
   279→   279→
   280→   280→$$d_t(\tau) = \sum^{t+W}_{j=t+1} (x_j - x_{j+T})^2$$
   281→   281→
   282→   282→Expanding, the RHS and substituting our definition of the autocorrelation function $r_t(\tau)$, we get the following equation for constructing the difference function:
   283→   283→
   284→   284→$$
   285→   285→\begin{align*}
   286→   286→d_t(\tau)&= \sum^{t+W}_{j=t+1} x_j x_j - x_j x_{j+\tau} - 2x_j x_{j+\tau} \\
   287→   287→&=r_t(0)+r_{t+\tau}(0)-2r_t(\tau)
   288→   288→\end{align*}
   289→   289→$$

   291→   291→def difference_function(audio_frame: np.ndarray, tau_max: int):
   292→   292→    """
   293→   293→    Compute the raw difference function for the YIN algorithm without assuming constant energy.
   294→   294→    
   295→   295→    Args:
   296→   296→        audio_frame: The current frame of audio samples.
   297→   297→        tau_max: The maximum lag to compute up to.
   298→   298→        
   299→   299→    Returns:
   300→   300→        diff_fct: The difference function values for lags 0 to tau_max.
   301→   301→        power_spec: The power spectrum of the audio frame.
   302→   302→        amplitudes: Amplitudes of the frame.
   303→   303→    """
   304→   304→    x = np.array(audio_frame, dtype=np.float64)  # Ensure float64 precision
   305→   305→    w = x.size
   306→   306→    tau_max = min(tau_max, w)  # Ensure tau_max is within the window size
   307→   307→
   308→   308→    # compute fast autocorrelation using FFT
   309→   309→    autocorr, power_spec, amplitudes = autocorrelation_fft(x, tau_max)
   310→   310→
   311→   311→    # compute the energy (r_t(0) and r_{t+\tau}(0)) for each lag
   312→   312→    r_0 = np.sum(x**2)
   313→   313→    energy = np.full(autocorr.shape, r_0)
   314→   314→
   315→   315→    diff_fct = energy[0] + energy - 2 * autocorr
   316→   316→    diff_fct[0] = 0
   317→   317→
   318→   318→    return diff_fct, power_spec, amplitudes

   333→   333→# Trough-picking
   334→   334→Recall that the fundamental period ($1/f_0$) corresponds to the point in which this difference function is minimized. Thus we would want to pick out some minima ('troughs') within the above curve. But how do we choose which trough to call the fundamental period?
   335→   335→
   336→   336→## Step 1: Cumulative mean normalization
   337→   337→The solution to this problem has multiple parts, but the first step is to modify the autocorrelation curve itself to bias against choosing lags near the beginning, and normalizing the range of the function.
   338→   338→
   339→   339→The way the original YIN algorithm does this is through **cumulative mean normalization**. This is where we finally construct the CMNDF, which is given by the following equation (and as equation 8 in [1]):
   340→   340→
   341→   341→$$
   342→   342→d_t'(\tau) =
   343→   343→\begin{cases}
   344→   344→    1, & \text{if } \tau = 0, \\
   345→   345→    \frac{d_t(\tau)}{\left[\frac{1}{\tau} \sum\limits_{j=1}^{\tau} d_t(j)\right]}, & \text{otherwise}.
   346→   346→\end{cases}
   347→   347→$$
   348→   348→
   349→   349→The idea is to normalize each $d_t(\tau)$, $\forall \tau \in [0, \tau _{\text{max}}]$ by the 'cumulative mean' of all $d_t(\tau)$ values up until that point, and artificially set the zero lag value to have a difference of $1$.
   350→   350→===== CELL 16 [code] 1224 chars =====
   351→   351→def cmndf(audio_frame: np.ndarray, tau_max: int):
   352→   352→    """
   353→   353→    Cumulative Mean Normalized Difference Function (CMNDF).
   354→   354→
   355→   355→    The idea is to normalize each d_t(tau) value for all lags based on the mean of the
   356→   356→    cumulative sum of all differences leading up to that point. YIN solution to not
   357→   357→    picking the zero-lag peak.
   358→   358→
   359→   359→    Args:
   360→   360→        audio_frame: The current frame of audio samples in Yin algorithm
   361→   361→        tau_max: Check for all time lags up to this value for in autocorr
   362→   362→
   363→   363→    Returns:
   364→   364→        cmndf: Array of values where index=tau and value=CMNDF(tau)
   365→   365→        power_spec: The power spectrum of the audio frame
   366→   366→        amplitudes: Amplitudes of the frame
   367→   367→    """
   368→   368→    x = np.array(audio_frame, np.float64)
   369→   369→    w = x.size # window size
   370→   370→    tau_max = min(tau_max, w)  # ensure tau_max is within the window size
   371→   371→

   503→   503→## Step 2: Absolute thresholding
   504→   504→
   505→   505→Now that we have our pitch estimates, how do we choose which pitch actually corresponds to the true fundamental frequency of the signal? We have an intuition that if the difference function is smaller at the given lag, then it is more likely to be the true fundamental frequency as more of the wave patterns will align than with those at subharmonic multiples.
   506→   506→
   507→   507→**Absolute thresholding** tries to account for the problem of accidentally picking octave errors, which we saw as the minima of the difference function which occur at period multipels of the fundamental. We essentially go through all the possible pitch estmates in successive order from the smallest to the greatest 'lag', and then we choose the first one that is below a given difference threshold. If no estimates are below the threshold, we take the global minima as the pitch.
   508→   508→
   509→   509→This is where we finally use our CMNDF's y-values to choose a particular pitch.
   510→   510→===== CELL 25 [code] 784 chars =====
   511→   511→def absolute_threshold(cmndf_frame: np.ndarray, local_minima: list[int], threshold: float=0.1):
   512→   512→    """
   513→   513→    Apply the absolute thresholding step by searching for the first trough
   514→   514→    below a certain 'absolute threshold'
   515→   515→
   516→   516→    Args:
   517→   517→        cmndf_frame: Output from applying CMNDF over a frame of audio samples
   518→   518→        local_minima: Indices of local minima of the raw diff_fct
   519→   519→        threshold: Take the first trough below this value of d'(tau)
   520→   520→    
   521→   521→    Returns:
   522→   522→        if possible, the first tau st. d'(tau) < threshold. Else, the x of the global minima
   523→   523→    """
   524→   524→    for min in local_minima:
   525→   525→        if cmndf_frame[min] <= threshold:
   526→   526→            return min
   527→   527→    
   528→   528→    # no min found below threshold, return the global minima
   529→   529→    global_min = np.argmin(cmndf_frame)
   530→   530→    return global_min

   536→   536→## Step 3: Peak refinement with parabolic interpolation
   537→   537→
   538→   538→The last step we will explore in the YIN algorithm is **parabolic interpolation** around each local minima to refine our final pitch estimate.
   539→   539→
   540→   540→For parabolic interpolation, for each local minima we take three points - the minima + its two adjacent neighbors - then fit a parabola through the 3 points and take the x value for minima of the parabola as the new true fundamental period. 
   541→   541→
   542→   542→The YIN paper (Cheveigne, Kawahara 2002) explains the reasoning in more detail, but the gist is that otherwise for periods that are not a multiple of the sampling period (eg, fits neatly within 44100 samples/sec) then the estimate may be incorrect by up to half the sampling period.
   543→   543→
   544→   544→Again, recalling the slight bias from the $d_t^\prime(\tau=0)=1$ from the CMNDF, we interpolate based on the raw difference $d_t$ function rather than the CMNDF.
   545→   545→
   546→   546→Our basic method is that given our 3 points:
   547→   547→
   548→   548→$$(x-1, y_1), (x, y_2), (x+1, y_3)$$
   549→   549→
   550→   550→We solve for the equation of the parabola passing through them by solving the system of 3 equations by plugging the points into the following equation:
   551→   551→
   552→   552→$$y = Ax^2 + Bx + C$$
   553→   553→
   554→   554→And then we get the following values for the interpolated $x_{\text{min}}$ and $y_{\text{max}}$ of the parabola.
   555→   555→
   556→   556→$$
   557→   557→x_{\text{min}} = x + \frac{y_1 - y_3}{2(y_1 - 2y_2 + y_3)}
   558→   558→$$
   559→   559→$$
   560→   560→{\text{min}} = y_2 - \frac{(y_1 - y_3)^2}{4(y_1 - 2y_2 + y_3)}
   561→   561→$$
   562→   562→
   563→   563→This allows us to refine the minimum point of the difference function and adds precision to our answers.
   564→   564→===== CELL 28 [code] 1177 chars =====
   565→   565→# note: njit is something to speed up the computation - useful for running
   566→   566→# the function multiple times across a long audio file
   567→   567→# in a real case i would include this
   568→   568→# @njit
   569→   569→def parabolic_interpolation(diff_fct: np.ndarray, trough_index: int) -> tuple[float, float]:
   570→   570→    """
   571→   571→    Perform parabolic interpolation around a minimum point using Numba for optimization.
   572→   572→    Done on diff_fct to avoid + bias for small lags from CMNDF.
   573→   573→    
   574→   574→    Args:
   575→   575→        diff_fct: A 1D array of y-values (e.g., diff_fct values).
   576→   576→        trough_index: The index of the minimum point in diff_frame.
   577→   577→
   578→   578→    Returns:
   579→   579→        A tuple with the interpolated x & y coordinates of the minimum.
   580→   580→    """
   581→   581→    x = trough_index
   582→   582→
   583→   583→    # don't interpolate at boundaries - need at least 3 points
   584→   584→    if x <= 0 or x >= len(diff_fct) - 1:
   585→   585→        return float(x), diff_fct[x]  
   586→   586→   
   587→   587→    y_1 = diff_fct[x - 1]
   588→   588→    y_2 = diff_fct[x]
   589→   589→    y_3 = diff_fct[x + 1]
   590→   590→
   591→   591→    denominator = 2 * (y_1 - 2 * y_2 + y_3)
   592→   592→    if denominator == 0:
   593→   593→        return float(x), y_2
   594→   594→    
   595→   595→    x_interpolated = x + (y_1 - y_3) / denominator
   596→   596→    y_interpolated = y_2 - ((y_1 - y_3)**2) / (4 * denominator)
   597→   597→
   598→   598→    return x_interpolated, y_interpolated
