    14→## 1. Two distinct id spaces (critical) (OBS)
    15→
    16→| space | producer | consumer | meaning |
    17→|---|---|---|---|
    18→| **setparam/getparam ids** | module wrapper | `m01` (`vtbl+0x08`) / `m02` (`vtbl+0x10`) | engine *parameters* (tracker config, read-outs) |
    19→| **port/register ids** | `FUN_1800c57c0` etc. during ctor | other modules via the owner publish vtable (`+0x58`, `+0x60`) | shared *data arrays* (voice delay, pages, tables) |
    20→
    21→`m01` handles ids `{0,1,2,4,5,6,14,15,16,17}` and forwards everything else to the base class
    22→(`vtbl+0x18`). `m02` handles `{7,8,9,10,0xb,0xc,0xd}` and forwards the rest to `vtbl+0x20`.
    23→**OBS** — ids 18..30 are therefore *not* setparam ids even though they are numerically adjacent to
    24→14..17; confusing them is the single most likely source of an incorrect wiring claim.

    45→## 3. `m02` — engine getparam (OBS)
    46→
    47→`meter = *(float**)engine[0xA4E0] → engine+0x41E8` = `{period, e_raw, e_filt}`;
    48→`sr = engine[0xA524]`; `S = engine[0xA520] = 2048.0`.
    49→
    50→| id | formula (verbatim structure) | unit |
    51→|---|---|---|
    52→| 7 | `len( (meter[0]·S / sr )? )` → `ln( (sr·S/period) · 0.003822256433 ) · 1731.234049`, sentinel `−65535` when `meter[0] ≤ 7.1e-15` | **cents** relative to **261.6256 Hz** (1/0.003822256433) |
    53→| 8 | `sr · S / period` … concretely `meter[0]·S/sr` rearranged as `sr·S/period` | **Hz** |
    54→| 9 | `i3 / (max(i3, max(i3, …)) + 8)` with `i3 = (int)(x·8388607.0)` and the max taken over `T+0x5F93/0x5F95/0x5F97` candidates | **voicing ratio** (0..1) |
    55→| 10 | `sqrt(meter[1] · 0.9999999)` | **amplitude** (linear) |
    56→| 0xb | `sqrt((e_raw·8388607 − e_filt·8388607)/(e_raw·8388607 + 7.1e-15)) · (period·S/sr) · 1.0646746e-05` | **timbre / periodicness** |
    57→| 0xc | gate `10^(gatelevel·0.11513)` (= `10^(x/20)` applied to a field that is *already* linear power) vs `sqrt(meter[1] · 0.99999988)`; then `−1731.234 · ln(corr)`, `corr = engine[0xA58C]` (`T+0x6074`) | **gated pitch read-out, in cents** (`1200·log2(1/corr)`); unreachable for normalised levels (DER, see note) |
    58→| 0xd | same gate; `+1731.234 · ln(gain)`, `gain = engine[0xA588]` (`T+0x6070`) | **gated pitch read-out, in cents** (twin of 0xc) |
    59→
    60→**Note on units (OBS/DER, corrected in round 8)** — `−1731.234 · ln(x) = 1200 · log2(1/x)`:
    61→`1200/ln 2 = 1731.234049…`, and the stored constant is the hand-typed `1731.234` (rel. err.
    62→`2.8e-8`). So `0xc`/`0xd` are **cents**, not dB; the earlier "dB-like" reading of this constant was
    63→wrong. `0.11513` is a hand-typed approximation of `ln 10 / 20` (rel. err. `6.5e-6`), i.e. the code
    64→treats the field as **dB** — but `T+0x5FD0` already holds `10^(g/10)` (linear power). With the
    65→normalised power envelope (`c/(1-d) = 1`, `sqrt(level) ≤ 1`) and a threshold `≥ 1.0`, the gate of
    66→`0xc`/`0xd` cannot open for normalised signals: **double conversion**, predicted output 0 (**DER**,
    67→runtime-unverified). See D6 §10.8.

   147→## 7. End-to-end wiring per parameter (matrix)
   148→
   149→Format: **param → registration → range/default → storage → mapping → smoothing → destination →
   150→consumer**.
   151→
   152→### 7.1 `gatelevel` (default -55)
   153→`module record` → port `gatelevel` → **`m01` id 2** → `T+0x5FD0` (float, **linear power** `10^(g/10)`)
   154→→ compared in the tracker's gate against a one-pole **power** envelope
   155→(`[[T+0x5FC8]+4] = (1/128)x² + (127/128)prev`, unity DC gain) with the rule *update above / hold
   156→below*; and read by `m02` id 0xc/0xd as `10^(x·0.11513)` (i.e. as if it were dB — the documented
   157→double conversion). **No smoothing.** Consumer: tracker gate (`0x18013D0DA`) + `m02` read-outs.
   158→**OBS** (round 8: D6 §10.8, R-39/R-40/R-41/R-42; `m01` = slot 1 of the
   159→`dsp_t` vtable `0x180409F60`, RTTI-confirmed; applier→module index is runtime, UNK)
   160→
   161→### 7.2 `minpitch` (default 24 of 0..47)
   162→`minp` module → port → **`m01` id 1** → `T+0x5F70 = x`, `T+0x5F74 = x+2`. **DER** — this sets the
   163→tracker's period search base and max index, i.e. the searchable pitch range. **No smoothing.**
   164→
   165→### 7.3 `pitchtracking` (toggle)
   166→`ptrk` module → port 30 (`shared_t<int> @ engine+0x4510`) → read in `FUN_1800e2030` L176-182:
   167→when 0, `rate_slot-independent factor = 1.0` and `i4 = 0`, i.e. **all voices play at unity**. **OBS**
   168→
   169→### 7.4 `xfadetime` (0..100 ms, default 10)
   170→`xfad` module ("xfade: %3.0f ms") → engine record **`xfadetime`** (OBS, D2 §10: `xfadetime=xfad-out`).
   171→The internal consumption is the voice-crossfade timing; the only crossfade *rate* traced so far is
   172→`corr = page[col+12]·2^-23` (period-driven). Destination **CLOSED** (round 4); the exact
   173→`xfadetime → page[col+12]` build remains **DER** (D7 Q-9).
   174→
   175→### 7.5 `tune` (392..494 Hz, default 440)
   176→`tune` module → engine record **`tune`** (OBS, D2 §10: `tune=tune-out`). The engine's `tune` input is
   177→the A4 reference in Hz. The reference *constant* used elsewhere in `m02` id 7 is the literal
   178→`1/0.003822256433 = 261.6256` (middle C, C4); the relation between the two radices is **DER**, not a
   179→contradiction (C1, D6 §9). Destination **CLOSED** (round 4); the internal radix mapping remains DER.
   180→
   181→### 7.6 `mod1..8` (per-voice modulation)
   182→`rdm slew N` → `(*(*owner+0x60))(owner, id, 0|1, value)` with the **bipolar pair**
   183→`(v, v^0x80000000)` and per-channel pending bits at object `+8`. Value path:
   184→source (pointer or inline) → clamp `[+0x18, +0x1c]` → `FUN_1800ca260(obj, ms) = clamp(1/(sr·ms·0.001), ≤1, ≥1.192093e-07)`.
   185→**OBS** (function fully read). Destination: the voice control ports consumed by
   186→`FUN_1800e8b50` / `FUN_1800e2030` §4.
   187→
   188→### 7.7 `shift1..8`
   189→`c_multiply N` (`FUN_18013a250`): `out = clamp(clamp(a, lo1, hi1) · clamp(b, lo2, hi2), −32768, 32767)`
   190→with change detection + dirty-bit fan-out. **OBS**
   191→
   192→### 7.8 `scale` / `key`
   193→`scal table` (`FUN_18013a790`, linear table interpolation, flag-gated, with notify) and `keys`.
   194→Their consumer must be the code that fills ports 21/22/25/26/27. That filler was **not** located; the
   195→best candidate is the 60-call-site function `0x18013ad00`. **UNK** → D7 Q-3/Q-4.
   196→
   197→### 7.9 `steps = 12`, `hysteresis = 10`, `correctrate = 1`, `mincorrect = 0`, `intervalglide = 1`,
   198→`tuning = 0`, `quantization = 0`
   199→Internal constants in the module record. Mapped candidates (**DER**, not confirmed):
   200→
   201→* `steps = 12` ↔ `sharedarray_t<int,12>` (port 27) and/or `m01` id 14 (row count);
   202→* `hysteresis = 10` ↔ the tracker hold/verification counters (states 4/5/6);
   203→* `correctrate = 1` / `mincorrect = 0` ↔ `T+0x6044/0x6048` (`m01` id 17) and `T+0x6064/0x6068`
   204→  (`m01` id 15, zeroed);
   205→* `intervalglide = 1` ↔ ports 28/29 (the global glide multipliers);
   206→* `tuning = 0` / `quantization = 0` ↔ `T+0x604C/0x6050` (`m01` id 16).
   207→
   208→Every one of these is **DER pending confirmation**; each is listed in D7.

   229→## 9. Cross-thread safety (OBS)
   230→
   231→The whole control graph is lock-free: pending bits are cleared with `LOCK CMPXCHG`; subscriber flag
   232→updates use `LOCK OR`; the shared arrays are published through the owner vtable (`+0x58`, `+0x60`)
   233→and the per-object element offsets written once at construction. **No mutex was observed on any
   234→control path** — which is consistent with §4's "flag-gated publish" architecture.
