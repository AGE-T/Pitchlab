    73→// ARCHITECTURE (see native/ARCHITECTURE.md for the full note)
    74→// -----------------------------------------------------------
    75→//  AlignedDelayLine   one mono engine, 1..8 voices, planar float in/out.
    76→//  MultichannelShifter N AlignedDelayLine engines (one per channel) with a
    77→//                     shared parameter surface -- channel isolation is
    78→//                     structural, not conventional.
    79→//  prepare()          allocates every buffer (ring, detector window, work
    80→//                     arrays, per-voice state). A prepare() whose
    81→//                     buffer-determining fields (sample_rate, max_voices,
    82→//                     f0_history, detection_interval) match the current
    83→//                     engine re-configures IN PLACE: zero allocations, zero
    84→//                     locks, identical result to a fresh engine (verified by
    85→//                     the acceptance suite's global-new counter). Other
    86→//                     prepare() calls take the allocate-and-rebuild path.
    87→//                     After prepare() returns, no allocation happens again:
    88→//                     process(), reset() and every parameter setter are
    89→//                     steady-state allocation-free (counter-gated tests).
    90→//  reset()            returns the engine to the post-prepare state
    91→//                     (allocation-free).
    92→//  process()          block size agnostic: the control-rate detector fires
    93→//                     every `detection_interval` STREAM samples, so the
    94→//                     output is invariant to how the caller splits the
    95→//                     stream into blocks (an intentional improvement over
    96→//                     the Python reference, which restarts its 64-sample
    97→//                     control loop at every process() call).
    98→//
    99→// REAL-TIME (RT) CONTRACT -- which call runs on which thread
   100→// -----------------------------------------------------------
   101→// * AUDIO THREAD (the process() caller): process(), reset(), setRatio(),
   102→//   setVoices(), setSpread(), setFeedback(), voiceStats(), lastEstimateHz(),
   103→//   latencySamples(), config(), ready(). All of these are wait-free and
   104→//   allocation-free after the first prepare(); none of them throw; none of
   105→//   them take locks or touch shared mutable state (the interpolator tables
   106→//   are immutable after first use -- thread-safe magic static, built once
   107→//   during warm-up, not per block).
   108→// * NON-REAL-TIME / controller thread: construction/destruction, prepare()
   109→//   in its allocate-and-rebuild path, and any first-use table construction.
   110→//   prepare() with matching buffer-determining fields IS safe on the audio
   111→//   thread (zero allocation) and is the supported "rate change confirmed
   112→//   same size" fast path; a mismatched prepare() allocates and frees and
   113→//   must be synchronised off-thread or during a pause by the host.
   114→// * One engine = one thread at a time. MultichannelShifter::process() runs
   115→//   its per-channel engines sequentially on the calling thread; engines are
   116→//   independent (structural channel isolation) and MAY be farmed out to
   117→//   other threads by the host, one engine per thread, without locks.
   118→// * VoiceStats is returned by reference into thread-local scratch: copy the
   119→//   value out if it must survive the next call on the same thread.
   120→// * No exceptions escape any entry point of this library (the process path
   121→//   is noexcept by construction; prepare() signals failure by return value).
   122→//
   123→// COLD-START ALIGNMENT LAW (round-13 recovery, R13-a; measured by the
   124→// cold_start_* suite cases)
   125→// ---------------------------------------------------------------
   126→// Let L = latencySamples() = base_delay + grain/2 (the nominal mid-grain
   127→// read delay at reset; every voice starts at grain phase frac = 0.5). A
   128→// UNITY voice parks before the first sample, so its first read is exactly
   129→// at delay L_v = base_v + grain/2; a SHIFTED voice's grain phase advances
   130→// by (1 - r)/S BEFORE the read at every sample -- including the first one
   131→// (processVoiceSample updates frac, then reads) -- so its first read is at
   132→// L_v + (1 - r) (exactly L_v when r == 1).
   133→// * Unity (ratio == 1.0 bit-exact): the voice parks on the integer delay
   134→//   d_park = round(base + grain/2) and the output is the bit-exact delayed
   135→//   copy out[k] == in[k - d_park + 1]; with the default config d_park == L,
   136→//   so the FIRST non-zero output sample for an impulse at t=0 is exactly
   137→//   k = L - 1 (the -1 is the reference ring convention: a read at delay d
   138→//   returns the sample pushed d-1 samples ago). Output before k = L - 1 is
   139→//   exactly zero -- the ring is pre-zeroed, standing in for "silence before
   140→//   t = 0"; the engine behaves like the same engine running forever.
   141→// * Ratio r != 1.0 from the very first sample (no glide at cold start: the
   142→//   gliding ratio is initialised AT its target): before the first grain
   143→//   wrap (S == grain, no commits yet) the read delay of output sample k is
   144→//         d(k) = L + (1 - r) * (k + 1),
   145→//   i.e. the output sample k interpolates the input at time
   146→//   tau(k) = r * (k + 1) - L. In the age-indexed ring the input's first
   147→//   sample (t = 0) sits at delay k+1 while output sample k is produced, so
   148→//   it first appears at output k0 = the first k whose interpolation kernel
   149→//   window (6-tap Lagrange: ring delays [floor(d)-2, floor(d)+3]; linear:
   150→//   [floor(d), floor(d)+1]) contains the ring delay k+1 -- the window's
   151→//   earliest reach is floor(d) - 2. The output is EXACTLY zero for every
   152→//   k < k0: the ring is pre-zeroed and no other read exists at cold start
   153→//   (a shifted voice starts fully engaged, e = 1 and a = 0, so the only
   154→//   reads are the A tap at d and the B tap at d + S >= d). Up-shifts
   155→//   contact the signal start EARLIER than unity's L - 1 (the read point
   156→//   starts mid-grain and walks toward the write point at closing speed r),
   157→//   down-shifts LATER; both follow the same law, and the cold_start_* cases
   158→//   gate the measured first non-zero sample, the exact zeros before it and
   159→//   the value at k0 against an independent re-derivation of this law inside
   160→//   the test, at block sizes 1/64/512, for 1 and 8 voices.
   161→// * No spurious transient: the engagement state is sane from sample 0
   162→//   (unity starts parked, shifted starts fully engaged) and the output is
   163→//   exactly zero everywhere before the kernel can possibly reach the input
   164→//   start (gated to max|out| == 0 before the contact point, on step and
   165→//   sine onsets, 1 and 8 voices).
   166→//
   167→// UNITY BEHAVIOUR (round-12 fix)
   168→// ------------------------------
   169→// The Python reference keeps a continuous complementary two-tap blend whose
   170→// phase freezes at unity -> a measured comb (-2.42 dB @ 220 Hz). The target
   171→// (static evidence, round 12, Finding 3) rests on a SINGLE interpolated tap
   172→// and only crossfades transiently after a re-arm. This core mirrors that
   173→// architecture: when a voice's target ratio is EXACTLY 1.0 (bit-exact) it
   174→// engages a single-tap path morphed in/out over `engagement_seconds`, and
   175→// parks on the nearest INTEGER delay so that exact unity is a bit-exact
   176→// delayed copy of the input (out[k] == in[k - d_park], neutral processing).
   177→// There is no bypass region: any ratio != 1.0 -- including +-1 cent -- gets
   178→// the full dual-tap processing path. Departing unity also refreshes the tap
   179→// spacing S from the live period estimate when the read point can be
   180→// preserved exactly.
   181→//
   182→// ROUND-15 PARAMETER SURFACE (P1) -- per-voice overrides, wet/dry, bypass
   183→// ----------------------------------------------------------------------
   184→// Config additions (validated exactly like engagement_seconds: negative
   185→// values are rejected by prepare()):
   186→//   gain_ramp_seconds   per-voice gain / mute ramp time (linear-in-amplitude)
   187→//   bypass_seconds      bypass enter/exit crossfade time
   188→//
   189→// PER-VOICE RATIO (setVoiceRatio(v, r)):
   190→//   v in [0, max_voices); r > 0. Sets voice v's ABSOLUTE target ratio: the
   191→//   geometric glide toward the target applies per voice exactly as for the
   192→//   global ratio (a large jump is handled by the same glide -- no
   193→//   special-casing), and a per-voice target of exactly 1.0 engages that
   194→//   voice's unity parking, exactly as the global ratio would. Each voice
   195→//   carries an override flag: setVoiceRatio sets it; setRatio(), setSpread()
   196→//   and prepare() RE-DERIVE every voice's target from (ratio, spread) and
   197→//   CLEAR all overrides (a cleared override voice loses its absolute value
   198→//   and returns to the spread table). reset() PRESERVES overrides.
   199→//
   200→// PER-VOICE GAIN (setVoiceGain(v, g)): linear amplitude target, g >= 0,
   201→//   rejected otherwise. The current gain ramps LINEARLY toward the target at
   202→//   a rate of |target - start| / (gain_ramp_seconds * sample_rate) per sample
   203→//   (the ramp restarts from the current gain whenever the target changes), so
   204→//   a change of size D completes in exactly gain_ramp_seconds. The per-voice
   205→//   gain multiplies AFTER the existing voice-count normalisation:
   206→//   final voice gain = normalisation * user_gain[v].
   207→//   At the default (all user gains 1.0) the multiplication is bit-neutral.
   208→//
   209→// PER-VOICE MUTE (setVoiceMute(v, on)): forces the voice's EFFECTIVE gain
   210→//   target to 0 through the SAME ramp (unmute ramps back to user_gain[v]).
   211→//   The voice's DSP state (ring phase, glide, spacing, engagement) keeps
   212→//   running while muted; only its contribution to the mix is removed. A voice
   213→//   whose ramped gain is exactly 0 contributes exactly nothing (its sample is
   214→//   not even added), so a mute/unmute cycle is bit-transparent once the ramps
   215→//   have completed.
   216→//
   217→// PER-VOICE BASE DELAY (setVoiceBaseDelay(v, d)): d > 0 and the voice's whole
   218→//   read range (B tap at d + S, S <= 1.5*grain, plus the 6-tap kernel margin)
   219→//   must stay inside the 2^18 ring -- invalid values are rejected (no-op).
   220→//   The new delay is applied at the START of the next process() call by
   221→//   re-aligning ONLY voice v's read position: the fractional grain phase and
   222→//   tap spacing are preserved (the read point translates by (new - old) base
   223→//   delay); a parked voice re-parks on the nearest integer of its new range.
   224→//   No other voice's output is touched (isolation is structural: base_delay is
   225→//   per-voice state). reset() preserves the override; prepare() clears it.
   226→//
   227→// WET/DRY MIX (setWetDry(w)): w clamped to [0, 1], default 1.0.
   228→//   out = w * wet_signal + (1 - w) * dry_signal,
   229→//   dry_signal[k] = the RAW input delayed to align with the wet path's
   230→//   intrinsic latency: dry[k] = in[k - (latencySamples() - 1)] (the ring
   231→//   convention read(d) = sample d-1 ago; implemented as an exact masked
   232→//   integer read of a dedicated raw-input ring, so it is bit-exact).
   233→//   MIX LAW: linear in amplitude (documented, no equal-power curve).
   234→//   Endpoints: w = 1 is the bit-identical 14.0.0 output path (special-cased,
   235→//   no dry read happens); w = 0 is the bit-exact delayed copy. The global
   236→//   feedback stays WET-PATH-ONLY: it taps the pre-mix wet signal, so the
   237→//   wet path's state evolves identically at every mix setting (and the dry
   238→//   path never carries feedback).
   239→//
   240→// BYPASS (setBypass(on)): click-free output bypass. The OUTPUT crossfades
   241→//   between the normal signal (the wet/dry mix at the current setting) and
   242→//   the dry delayed signal over bypass_seconds, in BOTH directions
   243→//   (fixed-slope blend, full range = exactly bypass_seconds). While bypassed
   244→//   the engine keeps processing -- every voice's DSP state, the detector and
   245→//   the (wet-path-only) feedback advance exactly as non-bypassed, because the
   246→//   bypass blend only touches the final output sample -- so a full
   247→//   enter+exit cycle is BIT-IDENTICAL to a never-bypassed run outside the two
   248→//   ramp regions.
   249→//
   250→// SEMANTICS CONTRACT (all new setters, like the existing ones): audio-thread
   251→//   safe, allocation-free, lock-free, no exceptions. A parameter change is
   252→//   picked up at the START of the next process() call (block-boundary
   253→//   application, not sample-accurate): the setters only store targets, and the
   254→//   per-sample machinery reads them inside process(). Simultaneous
   255→//   multi-parameter updates made between process() calls are therefore all
   256→//   applied atomically at that boundary -- no partial states are observable.
   257→//   The only quantity with an explicit pending stage is the per-voice base
   258→//   delay, applied to the voice state at the top of process(). Per-voice
   259→//   ratio changes ride the per-voice geometric glide; large ratio jumps are
   260→//   handled by that same glide.
   261→//
   262→// ROUND-19 CONTRACT (16.0.0) -- real-time, clicks, and the legacy gate
   263→// ---------------------------------------------------------------------
   264→// (a) DETECTOR (see DetectorMode above). The estimate cadence (every
   265→//     `detection_interval` STREAM samples), the median-history law, the
   266→//     hysteresis/commit law and the [60,1200] Hz validity gate are IDENTICAL
   267→//     in both modes; only the estimate VALUES differ (the decimated window
   268→//     sees a low-passed waveform at a coarser lag resolution -- measured

   270→//     detector_mode is buffer-determining for re-prepare (a mode change
   271→//     reconfigures the detector, so it takes the allocate-and-rebuild path).
   272→// (b) CLICK-FREE SPACING COMMITS: at a grain wrap whose hysteresis gate
   273→//     fires, the engine snapshots the voice's read state into a frozen
   274→//     SHADOW (S frozen at the old value; the shadow never commits) and
   275→//     crossfades shadow -> new law over commit_crossfade_seconds (clamped
   276→//     to 40 percent of the wrap period; a fully parked voice needs no
   277→//     crossfade because its integer read is S-independent). The blended
   278→//     output is continuous at the commit instant BY CONSTRUCTION (weight 0
   279→//     on the new law at the boundary). commit_crossfade_seconds == 0
   280→//     restores the legacy instant commit bit-exactly.
   281→// (c) VOICE ACTIVATION/DEACTIVATION RAMPS: setVoices(n) activates voices
   282→//     [0,n) and deactivates [n,max); each affected voice's EFFECTIVE gain
   283→//     target (active && !mute ? user gain : 0) ramps over
   284→//     gain_ramp_seconds through the existing linear ramp machinery, while
   285→//     the voice-count normalisation ramps as before. A deactivated voice
   286→//     keeps processing (DSP state stays warm) until its ramped gain reaches

   289→//     targets); only the transition is new.

   292→//     over delay_crossfade_seconds (0 = the legacy instant re-align,
   293→//     bit-exact). The final state equals the legacy law exactly.
   294→// (e) READ SUPPRESSION (bypass / zero wet): when the feedback coefficient
   295→//     is 0 AND the output is exactly the dry signal (wet == 0 with no
   296→//     bypass blend running, or the bypass blend has fully reached 1), the

   299→//     suppression is BIT-IDENTICAL by construction (the rings receive the
   300→//     same input, voice state evolution is read-independent, and the

   317→/// Interpolation for the fractional delay reads.
   318→enum class Interpolation : int {
   319→    Linear = 0,     ///< 2-point linear (the reference CLI's "linear")
   320→    Lagrange6 = 1,  ///< 6-point Lagrange, 2048 bin-centre phases (v2 default)
   321→    Lagrange6Q = 2, ///< 6-point Lagrange, 256 bin-centre phases ("lagrange6_q")
   322→    ObsKernel6 = 3, ///< target's observed static 256x6 .rdata kernel (OBS data)
   323→};

   325→/// Pitch-detector architecture (R19). Both modes implement the same
   326→/// YIN-family estimator (identical threshold law, cumulative-mean
   327→/// normalisation, parabolic refinement and the [60,1200] Hz validity
   328→/// gate); they differ in the rate at which the analysis window is sampled.
   329→enum class DetectorMode : int {
   330→    /// Full-rate reference detector (the R12--R18 behaviour, verbatim):
   331→    /// the sliding window holds RAW input samples at the host rate and the
   332→    /// analysis window follows the R13-b law win = max(2048, ceil(2.5*tau))
   333→    /// with tau at the host rate. Retained unchanged as the reference mode.
   334→    FullRate = 0,
   335→    /// R19 DEFAULT: a properly low-pass filtered, decimated control-rate
   336→    /// detector. The input is filtered by a 6th-order Butterworth low-pass
   337→    /// (three TDF2 biquads, fc = 0.35 * sr_dec) and decimated by D to a
   338→    /// control rate near 24 kHz (D = max(1, lround(sr/24000)); at the
   339→    /// canonical rates 44.1/48/88.2/96/176.4/192 kHz this is 2/2/4/4/7/8,
   340→    /// giving sr_dec in [22050, 25200]). The analysis window then holds
   341→    /// DEcimated samples with the time-equivalent law
   342→    ///     win_dec = max(1024, ceil(2.5 * tau_dec)),  tau at sr_dec,
   343→    /// which preserves the R13-b difference-support immunity
   344→    ///     m = win/2 - tau_max >= tau_max/4
   345→    /// at every rate and keeps the SAME ~42.7 ms window TIME SPAN and the
   346→    /// SAME detection-update cadence (one estimate every
   347→    /// `detection_interval` STREAM samples) as the full-rate detector at
   348→    /// 44.1/48 kHz. The audio path (ring, voices, interpolators, output)
   349→    /// always runs at the host's original sample rate; only the detector's
   350→    /// input is filtered and decimated. Valid detection range stays
   351→    /// 60..1200 Hz. Cost at 96 kHz drops by ~14x (see
   352→    /// evidence/analysis_round19 for the measured profile).
   353→    Decimated = 1,
   354→    /// R20-P2: coarse-to-fine hybrid. Stage 1 (COARSE) runs the EXACT
   355→    /// decimated estimator above (same anti-alias cascade, same decimated
   356→    /// window, same threshold/search law, same d-based parabolic refine)
   357→    /// and produces a candidate period tau_dec at the control rate. The
   358→    /// candidate is mapped back to the HOST stream grid:
   359→    ///     tau_c = tau_dec * D   (stream samples).
   360→    /// Stage 2 (FINE) evaluates the ORIGINAL, UNFILTERED full-rate signal's
   361→    /// difference function in a candidate neighborhood
   362→    ///     [tau_c - W, tau_c + W],  W = D + 2  host samples,
   363→    /// (clamped into the [60, 1200] Hz lag domain), takes the argmin and
   364→    /// refines it with a 3-point parabola on the RAW difference values --
   365→    /// full host-rate lag resolution. The refinement window support uses
   366→    /// the full-rate window law win_raw = max(2048, ceil(2.5*tau_max)) at
   367→    /// the HOST rate with m_raw = win_raw/2 - tau_max difference support
   368→    /// (the FullRate detector's own law), so both stages see the SAME
   369→    /// ~42.7 ms analysis time span and the estimate cadence, the median
   370→    /// history, the hysteresis/commit law and the validity gate are
   371→    /// IDENTICAL to the other two modes. The coarse candidate's accuracy
   372→    /// (<= ~0.2 dec-lag ~ 0.2*D host samples after its own parabolic
   373→    /// refine) is fully covered by the W = D+2 half-width; a pathological
   374→    /// waveform whose decimated argmin differs from the full-rate argmin
   375→    /// by more than W locks the refinement to the LOCAL minimum near the
   376→    /// candidate (an honest, measured behavioural difference vs FullRate,
   377→    /// not a defect). Cost: the decimated coarse stage + ~(2W+1)*m_raw
   378→    /// MACs -- at 96 kHz roughly 12% over Decimated and ~9x under
   379→    /// FullRate (measured; see evidence/analysis_round20).
   380→    Hybrid = 2,
   381→};

   383→/// Engine configuration (all values validated by prepare()).
   384→struct Config {
   385→    double sample_rate = 48000.0;
   386→    double ratio = 1.0;               ///< target pitch ratio (1.0 = unity)
   387→    int voices = 1;                   ///< active voices (1..max_voices)
   388→    int max_voices = 8;               ///< allocated voices
   389→    bool spread = true;               ///< musical spread table for voices > 1
   390→    double feedback = 0.0;            ///< wet feedback in (-1, 1), 0 = off
   391→    Interpolation interpolation = Interpolation::Lagrange6;
   392→    double grain = 4096.0;            ///< G, samples (delay-line grain)
   393→    double base_delay = 256.0;        ///< first voice base delay, samples
   394→    double fmin = 55.0;               ///< spacing-accept gate (Hz)
   395→    double fmax = 1200.0;             ///< spacing-accept gate (Hz)
   396→    double s_hysteresis = 0.005;      ///< S commit hysteresis (relative)
   397→    int f0_history = 8;               ///< period median window
   398→    int detection_interval = 64;      ///< control-rate period, STREAM samples
   399→    /// R19: detector architecture (see DetectorMode). Default = the
   400→    /// decimated control-rate detector; FullRate reproduces the R12--R18
   401→    /// reference behaviour bit-exactly. Buffer-determining for re-prepare.
   402→    DetectorMode detector_mode = DetectorMode::Decimated;
   403→    double engagement_seconds = 0.010;///< unity enter/exit morph time
   404→    double gain_ramp_seconds = 0.015; ///< per-voice gain/mute ramp (linear
   405→                                       ///< in amplitude; validated >= 0)
   406→    double bypass_seconds = 0.010;    ///< bypass enter/exit crossfade time
   407→                                       ///< (validated >= 0)
   408→    /// R19: click-free spacing-commit crossfade (seconds, >= 0; validated
   409→    /// exactly like the other time fields). When a grain wrap commits a new
   410→    /// tap spacing S, the engine crossfades from the old grain law (a frozen
   411→    /// shadow voice) to the new law over this duration instead of stepping
   412→    /// the read position (the 15.0.0 step was the dominant click source:
   413→    /// every initial spacing lock and every retune produced a step of
   414→    /// (S_new - S_old) samples in read position). 0 = the legacy instant
   415→    /// commit (bit-exact 15.0.0 behaviour, clicks included). The length is
   416→    /// additionally clamped to 40 percent of the current wrap period so a
   417→    /// second commit can never begin while a crossfade is still running.
   418→    double commit_crossfade_seconds = 0.008;
   419→    /// R19: crossfaded per-voice base-delay changes (seconds, >= 0). A
   420→    /// pending per-voice base delay is applied by crossfading the voice's
   421→    /// read between the old and the new base delay (the voice's grain
   422→    /// phase/spacing are shared) instead of translating the read point
   423→    /// instantly; 0 = the legacy instant re-align (bit-exact 15.0.0). The
   424→    /// eventual state (base delay, phase, spacing, park position) is
   425→    /// IDENTICAL to the legacy law; only the transition differs.
   426→    double delay_crossfade_seconds = 0.012;
   427→    /// R19: voice activation/deactivation fade (seconds, >= 0; validated
   428→    /// like the other time fields). setVoices() transitions ramp the
   429→    /// affected voices' contributions over this duration through the
   430→    /// per-voice gain ramp machinery (the settled state is bit-identical
   431→    /// to 15.0.0). 0 = the legacy INSTANT activation/deactivation
   432→    /// (bit-exact 15.0.0, including its voice-count transition step: new
   433→    /// voices entered at full amplitude while the normalisation had not
   434→    /// yet ramped).
   435→    double voice_fade_seconds = 0.012;
   436→    /// Geometric glide multiplier per sample (reference parity: 0.9995).
   437→    static constexpr double kGlideMult = 0.9995;
   438→};
