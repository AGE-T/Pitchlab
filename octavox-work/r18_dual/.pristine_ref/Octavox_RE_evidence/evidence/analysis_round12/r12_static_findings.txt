FINDING 1 -- The engine interpolator is a STATIC 256x6-float table, and it is
            NOT 6-point Lagrange  (OBS)
------------------------------------------------------------------------------
* engine+0x40f0 (member map: "6-tap Lagrange/phase table") is initialised by
  FUN_1800E18B0, NOT by the ctor:
      0x1800E1F82  mov dword [rsi+0x40d8], 0x3e800000   ; quartic c0
      0x1800E1F8C  mov dword [rsi+0x40dc], 0x3eb12e86   ; c1
      0x1800E1F96  mov dword [rsi+0x40e0], 0x3e79c4bb   ; c2
      0x1800E1FA0  mov dword [rsi+0x40e4], 0x3df569c6   ; c3
      0x1800E1FAA  mov dword [rsi+0x40e8], 0x3d0ed15e   ; c4
      0x1800E1FB4  lea  rax, [rip+0x2d41b5]             ; -> 0x1803B6170
      0x1800E1FBB  mov qword [rsi+0x40f0], rax          ; table pointer
  The table lives in .rdata at VA 0x1803B6170 (file offset 0x3B4770), 256 rows
  x 6 floats, 0x18-byte stride (row r at +0x18*r, taps at +0,+4,+8,+0xc,+0x10,
  +0x14 -- matching the prepare's read pattern).
* Phase quantisation (OBS, prepare 0x1800E2490-0x1800E24AD):
      phase = (((int)(pos * 2048.0)) >> 3) & 0xFF
  with the mask 0x7F8 loaded from engine+0x4098; for pos = i + f this equals
  floor(f * 256) -- i.e. FLOOR-indexed bins of width 1/256.
* Kernel shape (OBS, extracted bit-exactly; see r12_interp_table.txt and the
  generated r12_obs_kernel_table.h):
    - all 256 rows non-zero; row sums 1.000000..1.000122 (unity DC gain);
    - effective fractional delay sweeps 0.0020 -> 0.9980 samples relative to
      tap 2 -- bin-CENTRE phases (r+0.5)/256 (DER from the delay sweep);
    - rows are mirror-symmetric (row 255 = reverse of row 0);
    - it is NOT 6-point Lagrange: L2 mismatch 0.11..0.19 rms per row against
      the best-aligned Lagrance row (hypothesis fits in r12_interp_table.txt);
      it is a designed symmetric lowpass kernel (windowed-sinc-like, DER).
  Consequence: the member-map label "Lagrange" was an unverified guess and is
  corrected to "static 256x6 fractional-delay kernel (non-Lagrange, OBS)".

FINDING 2 -- The settled path reads ONE interpolated tap per output sample
            (OBS, instruction level)
------------------------------------------------------------------------------
Prepare FUN_1800E2030, voice loop. The branch at 0x1800E2470/0x1800E2479:
      cvttss2si eax, dword [r12+rdi]     ; (int)state[v]   (state at +0x4158[v])
      cmp eax, -1
      jne 0x1800E2812                    ; -> crossfade path
SETTLED path (0x1800E2490-0x1800E25D5): per output sample the loop computes
exactly ONE 6-tap weighted sum (one phase row from +0x40f0 applied to 6
consecutive work-ring samples starting at (int)pos + voice base), advances
pos by -rate (clamped >= 0), and writes one output float. No second tap, no
blend. The settled state is the REST state of the engine.
CROSSFADE path (0x1800E2812-0x1800E2A5D): TWO 6-tap reads -- tapA at ringbase
- interval and tapB at ringbase (interval = (int)ring[recidx+1], loaded at
0x1800E2630) -- mixed as
      out = tapA + (tapA - tapB) * state,   state in (-1, 0]
(0x1800E29FD-0x1800E2A5D), i.e. a linear one-shot fade from tapA (state=0)
to tapB (state=-1) that SETTLES back to single-tap when state reaches -1.

FINDING 3 -- Q-14 static advance: the target cannot sit in a two-tap blend
            at unity  (DER, strong)
------------------------------------------------------------------------------
Chain (each link OBS unless noted):
  a. rate_v = 4*P(f)*ratio*correction with P(0) = 0.25 bit-exact (rounds 9-11),
     so at f=0 (no random modulation), ratio=1, correction=1 the step is
     EXACTLY 1.0 (DER).
  b. pos advances by +4.0 per 4-sample block (const 4.0 at 0x1804123E8, added
     at 0x1800E224D) and by -rate per output sample: net 4*(1-rate) per block
     = 0 at rate 1 -> pos is FROZEN at unity.
  c. The re-arm trigger is pos - delay < 8.000000000000007 (double const at
     0x180412428, compare at 0x1800E2777): with pos frozen and delay fixed
     (+0x4140[v], init 280), the re-arm NEVER fires at unity -> the engine
     stays in the settled single-tap path forever.
  d. Therefore at exact unity the engine output is ONE fixed 6-tap read at a
     fixed delay -- a fixed (fractional) delay, i.e. NO two-tap comb, by
     construction (DER).
Implication for our work: the unity comb measured in OUR reference demo
(-2.42 dB at 220 Hz) is a property of OUR continuous complementary two-tap
blend, which the target architecturally does not use at rest. The round-12
native core fixes our implementation the same way (single-tap engagement at
exact unity). Runtime audibility of the target path remains UNK (never
executed); this is the static answer to Q-14's premise.

FINDING 4 -- Crossfade mechanics fully decoded  (OBS)
------------------------------------------------------------------------------
After each 4-sample settled block (0x1800E25DB onward):
  * record read: base = (recidx[v] (+0x42f8) + wdelta (+0xa4fc)) & 0xFFF into
    the 4096-float record ring at engine+0x98;
       v  = clamp(record_ring[base] * 2^-11, >= 48.0; = 480.0 if ~0)
            (2^-11 at 0x180411E94, 48.0 at 0x180412688, 480.0 at 0x180412730,
             eps 7.105427357601002e-15 at 0x180411E44)
       interval = (int)record_ring[base+1]            (tapA offset)
       correction = record_ring[base+3]               (confirms round 9)
       if tracking (+0x4510) == 0: correction = 1.0, interval = 0
  * idx = clamp((int)((v - 48.0) * 0.0625), 0, 31)    (0.0625 at 0x180411F68,
        31.0 at 0x180412660) -- indexes the page's 32-entry table at page[12+idx]
  * slot+0x4110[v] = page[12+idx] * 2^-23             (fade decrement per OUTPUT
        SAMPLE; 2^-23 at 0x180411E54; slot init 0x3D7FFFE0 = 0.06249988)
  * re-arm jump distance (floor-rounded, 0x1800E270E-0x1800E273E):
        jump = floor( 2^( (int)page[12+idx] & 0xF ) * v + 0.5 )
        if jump >= workring_mask - page[11]:  jump *= 0.5   (0.5 at 0x180412058)
  * trigger: pos - delay[v] < 8.000000000000007 (double at 0x180412428);
    on re-arm: delay[v] = pos -/+ jump (0x1800E275E-0x1800E27F2),
    state[v] = 0 (0x1800E2802-0x1800E2809) -- the fade then decrements state
    per output sample until -1.
  * the fade hands off between taps one RECORD INTERVAL apart (tapA = ringbase
    - interval) -- the same period-alignment idea our round-11 v2 implements
    by committing S = k*T_hat (independent derivation; DER for the analogy).
  The record-ring first field's UNIT (what makes v >= 48 for musical periods)
  remains UNK (all realistic sample-domain periods give v < 48 -> clamped, so
  in practice idx = 0 and jump base = 48 or 480 scaled by 2^k; the exact
  scaling of record_ring[base] is not settled this round).
