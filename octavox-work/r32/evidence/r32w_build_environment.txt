THE LINK DEFECT THIS ROUND CLOSED (reproduced + fixed)
  zig 0.13.0 targeting x86_64-windows-gnu does NOT provide the
  compiler-rt cpu_model runtime: __builtin_cpu_supports compiles but
  FAILS TO LINK (undefined __cpu_indicator_init / __cpu_model; reproduced
  with a minimal probe THIS round too). The R24-W fix (the explicit
  CPUID+XGETBV path) is ported to the R26+ line -- without it the Windows
  module cannot link at all. A SECOND, subtler consequence was caught by
  the machine-code gate this round: the stale OCTAVOX_X86_MSVC capability
  gates (isaUnitsCompiled/kernels/read-kernels) meant the Windows build
  reported "no ISA units" and the linker DEAD-STRIPPED the AVX2/FMA kernel
  objects (final DLL ymm=0 -- the module would have silently run
  scalar-only on Windows). With the corrected gates the final DLL carries
  ymm=275 vfmadd=26 cpuid=3 xgetbv=1 (every 256-bit instruction accounted
  for; see r32w_machinecode_verification.txt).
