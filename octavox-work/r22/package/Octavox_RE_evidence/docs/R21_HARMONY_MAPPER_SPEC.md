# R21 — Independent Harmony Mapper: Mathematical Specification

**Round:** 21 (P2) · **Status:** SPECIFIED + IMPLEMENTED (`native/include/octavox/harmony.hpp`,
`native/src/harmony.cpp`) + VERIFIED (545 reference vectors,
`evidence/analysis_round21/r21_harmony_vectors.json`, generated by the independent

**What this is:** an INDEPENDENT implementation of the harmonic MAPPING
reconstructed from static analysis of the original Eventide Octavox binary
(rounds 17/18 evidence — every table and rule below cites its VA). It is NOT a
reproduction of the original's audio engine; it maps
**Key + Scale + Temperament + Musical Interval + Fine Tune → per-voice pitch
ratio** for use with the existing per-voice ratio API
(`ratio_v = global_ratio * voice_ratio_v`, see R20_PARAMETER_SEMANTICS.md).

**Evidence-class legend:** OBS = static observation of the original binary;
DER = high-confidence derivation; UNK = unobservable statically.

## 2. The recovered rules

### 2.1 The zone-run grid fill — `0x1800E65B0..0x1800E6790` (OBS)

For each pattern row + temperament cents, build the degree grid:

```
for slot in 0..11:
    p = pattern[slot]
    if p == 0:        continue
    if p == 99:       grid.append(cents[slot])            # filler: single position
    else:             grid.extend([cents[slot]] * (p - prev))   # gap doubling
                      prev = p
size = len(grid)      # 6, 7 or 12
```

Examples (12-TET): ionian → [0,200,400,500,700,900,1100] (size 7); chromatic →
all 12 cents (size 12); whole tone → [0,200,400,600,800,1000] (size 6);
penta major → [0,0,200,400,700,700,900] (size 7, doubled positions — the R18
"penta array [C,C,D,E,G,G,A]").

### 2.2 The walk — `0x1800E6ED5..0x1800E7120` (OBS; the disassembly this round
re-verified instruction by instruction)

**The sign law.** `sel = 14 − v` (the engine's `shiftN`): "+" labels give
sel < 0 (the DOWN branch), "−" labels give sel > 0 (the UP branch) — the
label/walk sign inversion recorded since R17. Which direction is AUDIBLE in
the original is UNK (the applier's sign convention).

```
q = sel / 7                    (C truncating division)

UP (sel >= 0):
    start = min(sel % 7, size-1)
    row0      = grid[start % size] + 1200·q + pcent
    row j+1   = int(wrapUp(grid[(start+j) % size]) + pcent) - grid[j] + 1200·q
                wrapUp(t, b) = t if t >= b else t + 1200
DOWN (sel < 0):
    m      = min(7·q - sel, size-1)
    start  = (1 - q)·size - m
    row0      = (grid[start % size] - 1200) mod 1200 + 1200·q + pcent   (C mod)
    row j+1   = int(wrapDown(grid[(start+j) % size]) + pcent) - grid[j] + 1200·q
                wrapDown(t, b) = t if t <= b else t - 1200
rows with index > size repeat row0 (the recovered tail fill).
```

**The 8-row table is the per-voice ratio table** (published to the shift
records — the publish loop at `0x1800E7180..0x1800E71E6` emits local_3f0[0..7]):
voice 1 = row0 (the tonic-relative interval); voice v≥2 = row v−1 (the interval
from degree v−1 — the voices sit on consecutive scale degrees, a diatonic
stack). Verified consequences (all reproduced by the implementation + vectors):

* unison (v=14, sel=0) → **every voice unity** (all rows reduce to pcent);
* "+3rd" (v=17, sel=−3) → every voice down a 4th-class step (−500 c in 12-TET
  ionian) — the R18 "a '3rd' choice literally sounds a 4th-class shift" (OBS);
* "−5th" (v=10, sel=+4) → every voice up a P5 (+700 c);
* the reachable tonic-relative targets are exactly `{0,2,3,4,6} mod 7` — the
  2nd and 6th are never walk targets (the collapsed pairs above).

**The chromatic/whole-tone raw-index switch** (records [17..19], OBS): when the
scal-mux OUTPUT is 14 or 15 (the "chromatic"/"whole tone" CHOICES), the
`int table switch` uses the RAW choice index instead of the mux value, so
sel = 14 − rawIndex (un-bumped); the loaded grid is the irregularity-shifted
penta row. `mapChoice` reproduces this verbatim.

### 2.3 The key-ratio law — `0x1800E6557..0x1800E6589` (OBS)

```
k = keymap[key]
keyCents = -cents[9-k]   if k < 9      (below the reference A)
         = +cents[k-9]   if k > 9
         = 0             if k == 9     (A itself)
keyRatio = exp(keyCents · ln2 / 1200)
```

Musically coherent: key C (k=0) → −900 cents in 12-TET (A down to C); key B
(k=11) → +200 cents. Symmetric in |k−9| (the R18 closure of R17's "asymmetry"
— a decompiler stack-layout artifact).

### 2.4 The composition law (OBS — `0x1800E6FD3`, `0x1800E6FAB`)

```
voiceCents_v = walk row for voice v (with pcent_v)
ratio_v      = keyRatio · exp((voiceCents_v + tune) · ln2 / 1200)
```

`pcent` = the per-voice fine cents (the `shtN` records; N=1 declared
−2400..+2400 res 1, N=2..8 declared −1..+1 res 0.001 — the shipped-record
range inconsistency is documented in OCTAVOX_CONTROL_FLOW_MATRIX.md §10.3,
Q-10); `tune` = the global tune (392..494 Hz A4-reference knob — an
independent-choice mapping as plain cents is used here, DER). The original
multiplies its ratios by 1/16 (the page scale, `xmm9 = 0.0625` at
`0x1800E6F59`) — an internal representation detail NOT reproduced (our unity =
1.0).

## 3. The independent module's API (implemented)

```cpp
namespace octavox::harmony {
enum class Temperament { Equal12, JustMajor, JustMinor, Pythagorean, Meantone14 };
struct VoiceRequest { int interval; double fine_cents; };   // 0..28, cents
struct MapRequest {
    int key;                        // 0..16 (13 = A; key-map value 9)
    int scale;                      // row-level 0..18 / choice-level 0..14
    Temperament temperament;
    double global_tune_cents;
    VoiceRequest voices[8];
};
struct MapResult { double ratio[8]; double voice_cents[8]; double key_ratio;
                   int grid[12]; int grid_size; };
MapResult mapRow(const MapRequest&);      // pattern-row API (clean surface)
MapResult mapChoice(const MapRequest&);   // engine-choice API (irregularity
                                          // + raw-index switch verbatim)
}
```

**Invalid/boundary selections (documented policy):** clamped deterministically
(`clamp(key,0,16)` etc.; configure() rejects nothing — the mapper is total).
The ORIGINAL's out-of-range behaviour (e.g. hungarian choice 16) is UNK; the
independent mapper keeps the mapping TOTAL so hosts can never crash it. The
interval indices 0 and 28 are the boundary selections (−2/+2 oct).

**Determinism statement:** same inputs → bitwise-identical outputs. The walk is
pure integer arithmetic; the single transcendental per output is
`exp(cents * 0.6931471805599453 / 1200.0)` evaluated left-to-right in IEEE
double (M_LN2 = the correctly-rounded ln 2, identical in C++ and Python). On
one platform the C++ and Python implementations agree bit-exactly (worst
relative deviation 0.0 over 545 vectors); cross-platform tolerance ≤ 1e-15
relative (libm `exp` differences only). The original multiplies by the
pre-rounded constant 0.00057762265 — a ≤1-ulp difference (documented, not
reproduced).

**Host-surface status:** NOT exposed. Parameter IDs 0–37 are untouched; the
mapper is a library + CLI-verified reference (`octavox_r21_harmony`) until its
semantics and parameter-ID allocation pass the compatibility review.

## 5. Differences vs the original (the honesty section)

This is an INDEPENDENT implementation of the reconstructed MAPPING. It is not
claimed to reproduce the original's audio engine. Known divergences and
residues:

1. **Unity convention:** our ratios are musical (1.0 = unity); the original's
   internal page scale is 1/16 (OBS).
2. **Transcendental constant:** `exp(c·ln2/1200)` vs the original's
   pre-rounded multiplier (≤1 ulp).
3. **Audible direction of labels:** the walk's sign law is reproduced
   faithfully ("+" walks down); which direction is audible in the original is
   UNK (applier sign convention).
4. **The exact per-voice wiring** of the original's 8-row walk table to its
   shift records (one walk vs per-voice walks) has bounded UNK residue; our
   interpretation (voice v = row v−1, the diatonic-stack reading) matches every
   OBS table value and the unison/all-voices-unity consequence.
5. **UNK residues (not implemented):** the authored irregularities' intent;
   the 99-filler semantics beyond the fill law; the mux design rule's intent;
   the userscale1..12 user-scale path (the 18-entry map `0x1803BB60C` is
   recorded but its wiring is UNK); the `quantization` record (constant 0).
